1.2.a How is the player's location on the board represented?

The player is stored in the list self.body, which holds Cell objects. The head
of the list (body[0]) is the player's current location, and the rest of the
cells in the list are the ducks that are following behind. At the start the
list only has one cell, the one at (0,0). Each Cell also knows its own row and
col, so we can find where the player is on the board from that.
 
1.2.b) What method(s) are given to help access different parts of the player's "body"?

get_player() returns the first cell in body (the head), and get_tail() returns
the last cell in body (the tail).

1.2.c) What are the different movement modes of the player, and what do they mean in terms of how the player moves each turn?

There are five modes in the MoveMode enum:
- GOING_NORTH: the player moves up one cell each turn
- GOING_SOUTH: the player moves down one cell each turn
- GOING_EAST: the player moves right one cell each turn (this is the default
  mode when the game starts)
- GOING_WEST: the player moves left one cell each turn
- AI_MODE: the player doesn't follow a fixed direction, instead the next cell
  is picked by get_next_cell_ai()

1.2.d) What is the current behavior of get_next_cell()? get_next_cell_ai()?

get_next_cell() looks at the current mode and returns the neighbor of the
player's head in that direction (north, south, east, or west). If the player is
at the edge of the map it returns None, which move_player_to_cell() treats as
game over. It doesn't handle AI mode since that uses get_next_cell_ai() instead.

get_next_cell_ai() right now doesn't do any searching. It resets the search
info on all the cells, makes an empty Stack or Queue depending on ai_type, and
then just returns a random neighbor of the player. So in AI mode the player
currently wanders randomly. The search code still needs to be added.
